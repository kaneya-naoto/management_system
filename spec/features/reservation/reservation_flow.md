# 予約フロー

## 概要

カクレマの予約は4つの経路から流入する：
1. **Webフォーム予約**: 顧客が公開予約フォームから自動予約
2. **LINE予約（LIFF）**: 顧客がLINEアプリ内LIFF経由で自動予約
3. **LINE/電話/直接予約（CMS手動）**: スタッフがCMSで手動入力
4. **決済Webhook予約**: 外部決済完了通知による自動登録（将来対応）

---

## Webフォーム予約（4ステップウィザード）

### アクセス方法

公開予約フォームへのアクセスは **店舗コードURL** を使用する：

| アクセスパターン | URL | 認証 |
|-----------------|-----|------|
| 店舗コード指定 | `/booking/{store_code}` | 不要（公開） |
| 店舗コードなし | `/booking` | ログイン必須 |

- 店舗コードURL例: `/booking/SHIBUYA01`
- 無効な店舗コードの場合は404エラー
- 店舗コードなしでの未ログインアクセスは403エラー

### 4ステップウィザード

```
[ステップ1] 日時選択 (/booking/{store_code})
    ↓ POST
[ステップ2] お客様情報入力 (/booking/{store_code}/customer)
    ↓ POST
[ステップ3] 確認・決済 (/booking/{store_code}/confirm)
    ↓ POST
[ステップ4] 完了 (/booking/{store_code}/complete → /booking/{store_code}/thanks)
```

### ステップ1: 日時選択

| 項目 | 必須 | 備考 |
|------|------|------|
| 部屋タイプ | ○ | カード形式で選択（営業区分） |
| 利用日 | ○ | 日付ピッカー（当日〜30日先） |
| 開始時間 | ○ | 30分刻みセレクト（営業時間に基づきフィルタ） |
| 終了時間 | ○ | 30分刻みセレクト（営業時間に基づきフィルタ） |

- 部屋カードには料金（時間単価）、定員、営業時間を表示
- 日時選択後、リアルタイムで空き状況をAPI確認
- 予約時間は1〜8時間の範囲
- 当日予約は1時間後以降のみ可能
- 深夜またぎ対応済み

### ステップ2: お客様情報入力

| 項目 | 必須 | 備考 |
|------|------|------|
| お名前 | ○ | 最大100文字 |
| メールアドレス | ○ | 確認メール送信先 |
| 電話番号 | ○ | 最大20文字 |
| ご利用人数 | - | 1〜10名（デフォルト1名） |
| クーポンコード | - | 任意 |

### ステップ3: 確認・決済

- 予約内容の最終確認画面
- 料金計算: `利用時間 × 営業区分の時間単価（hourly_rate）`
- 決済サービスは現在準備中（MVP版は自動確定）

### ステップ4: 完了処理

```
[システム] 空き状況再検証（FOR UPDATEロック）
    ↓
[システム] 予約レコード作成（status=pending）
    ↓
[システム] 自動確定（status=confirmed, payment_status=paid）※MVP版
    ↓
[システム] 鍵番号ランダム割当
    ↓
[システム] 清掃案件自動生成
    ↓
[システム] 当日予約の場合LINE即時通知
    ↓
[システム] 予約確認メール送信
    ↓
[顧客] 完了ページ（/thanks）表示
```

### セキュリティ対策

- CSRFトークン検証（全ステップ）
- セッション固定化攻撃対策（フロー開始時・完了時にセッションID再生成）
- 店舗コード境界検証（URLの店舗コードと選択営業区分の店舗一致確認）
- セッション改ざん対策（sales_area_idとstore_idの整合性再検証）

### 決済連携（Webhook）※将来対応

決済完了通知をWebhookで受信し、CMSへ予約を自動登録：


## 予約完了ページ

### 表示内容

- 「このメールアドレスに予約情報を送信しました」
- 登録メールアドレス
- 予約内容（日時、区分）

### 機能

| 機能 | 説明 |
|------|------|
| メールアドレス編集 | 誤入力時に修正可能 |
| 再送ボタン | 確認メールを再送 |

### メールアドレス修正時の挙動

1. 修正前アドレス宛の予約情報は無効化
2. 再送は修正後アドレスのみに送信
3. 修正履歴をログに記録

## 予約確認メール

### 送信タイミング

- 予約確定時
- メールアドレス修正後の再送時

### メール内容

| 項目 | 内容 |
|------|------|
| 件名 | 【カクレマ】予約確認のお知らせ |
| 本文 | 利用者名、予約日時、部屋種別、鍵番号 |

### テンプレート例

```
{customer_name} 様

ご予約ありがとうございます。

■ 予約内容
日時：{reservation_date} {start_time}〜{end_time}
場所：{sales_area_name}
鍵番号：{key_number}

当日のご来店をお待ちしております。
```

## LINE予約（LIFF自動予約）

### 概要

LINE LIFF（LINE Front-end Framework）を使用し、顧客がLINEアプリ内から直接予約を行える。
予約フォームはWebフォームと共通（4ステップウィザード）で、LIFF SDKが自動的にLINEユーザー情報を付与する。

### フロー

```
[顧客] LINE内でLIFFアプリを開く
    ↓
[LIFF SDK] 自動初期化 → LINEプロフィール取得
    ↓
[顧客] 4ステップウィザードで予約（Webフォームと共通UI）
    ↓
[システム] source='line' + line_user_id + line_display_name を自動付与
    ↓
[システム] 予約登録（Webフォームと同一の完了処理）
```

### LIFF連携で自動取得される情報

| 項目 | 説明 |
|------|------|
| source | `line`（自動設定） |
| line_user_id | LINEユーザーID |
| line_display_name | LINE表示名 |

- LINEアプリ外から開いた場合はWebフォームとして動作（source=web）
- LIFFログイン状態でのみプロフィール情報を取得

## CMS手動予約（LINE/電話/直接）

### フロー

```
[顧客] LINEメッセージ、電話、または店頭で連絡
    ↓
[スタッフ] CMSで手動予約登録（/reservations/create）
    ↓
[システム] 決済状態が「支払済」の場合:
    ├── 鍵番号ランダム割当
    └── 清掃案件自動生成
    ↓
[スタッフ] 確認メール送信（任意）
```

### 登録時の予約経路（source）

| 経路 | source値 | 説明 |
|------|----------|------|
| Webフォーム | web | 顧客が公開フォームから予約 |
| LINE（LIFF） | line | 顧客がLINEアプリ内から予約、またはスタッフがCMSで登録 |
| 電話 | phone | スタッフがCMSで登録（デフォルト） |
| 直接（店頭） | direct | スタッフがCMSで登録 |

## 予約ステータス遷移

```
pending ──→ confirmed ──→ completed
   │             │
   └──→ cancelled ←──┘
```

| ステータス | 説明 | 次のアクション |
|------------|------|----------------|
| pending | 予約受付、未決済 | 決済完了でconfirmedへ |
| confirmed | 決済完了 | 利用終了でcompletedへ |
| cancelled | キャンセル | - |
| completed | 利用終了 | - |

---

## 自動処理トリガー

### confirmed時

| 処理 | 説明 |
|------|------|
| 鍵番号割当 | 空いている鍵をランダム選択 |
| 清掃案件生成 | cleaning_jobsにレコード作成 |
| 固定者通知 | 固定者がいれば優先通知 |
