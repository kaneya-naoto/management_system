# 固定者・急募

## 概要

店舗ごとに固定清掃者を登録し、案件発生時に優先通知する機能

---

## 固定者管理

### 基本仕様

- 店舗単位で固定者を登録可能
- 1店舗に複数の固定者を設定可能
- 優先順位（priority）で通知順を制御

### 登録項目

| 項目 | 必須 | 説明 |
|------|------|------|
| 店舗 | ○ | 対象店舗 |
| 清掃者 | ○ | 固定者として登録する清掃者 |
| 優先順位 | ○ | 通知の優先度（数字が小さい方が優先） |
| 有効フラグ | ○ | 有効/無効 |

---

## 優先通知フロー

最優先の固定者1名に通知を送信し、タイムアウト（30分）まで応答を待つ。
応答がなければ次の優先度の固定者に通知する（1名ずつ順次）。

```
[案件生成]
    ↓
[固定者検索] 該当店舗の有効な固定者を優先順位でソート
    ↓
┌─ 固定者あり ─→ [最優先1名に通知送信] → [30分応答待ち]
│                                            ↓
│                    ┌─ OK（応答あり）──→ [担当確定] END
│                    │
│                    └─ タイムアウト ──→ [次の固定者を検索]
│                                            ↓
│                                      ┌─ 次がいる ─→ [次の1名に通知送信]（30分待ち）
│                                      │
│                                      └─ いない ───→ [公募開始]
│
└─ 固定者なし ─→ [公募開始]
```

> 固定者通知は「NGの明示回答」ではなく「タイムアウト（30分無応答）」で次へ進む。
> cronジョブ（`cron/process_fixed_timeout.php`、5分間隔）がタイムアウト判定と次通知を処理する。

---

## 通知タイムアウト

### 仕様

| 項目 | 値 |
|------|-----|
| 応答待ち時間 | 30分（設定可能） |
| 判定基準 | タイムアウト（30分無応答）で次へ進む |
| タイムアウト時 | 次の固定者へ通知 or 公募開始 |
| 処理実行 | cronジョブ（5分間隔） |

> NG回答の明示的な受付ではなく、タイムアウトベースで次の固定者へ遷移する。

### タイムアウト処理

```
[cronジョブ（5分間隔）]
    ↓
[fixed_waiting状態 かつ fixed_notification_sent_at から30分経過の案件を取得]
    ↓
[次の固定者を検索]（既に通知済みの固定者を除外）
    ↓
┌─ 次がいる ─→ [次の1名に通知送信] → [fixed_notification_sent_at を更新]
│
└─ いない ───→ [公募通知送信] → [notification_status を public_recruiting に]
```

### cronジョブ

- ファイル: `cron/process_fixed_timeout.php`
- 実行間隔: 5分
- 二重実行防止: flock によるファイルロック
- 処理関数: `processFixedCleanerTimeout(30)`

## CMS画面

### 固定者一覧

| カラム | 説明 |
|--------|------|
| 優先度 | 通知優先度（数値入力、変更で即保存） |
| 清掃者 | 固定者の名前・電話番号（休止中の場合はバッジ表示） |
| 店舗 | 対象店舗名 |
| ステータス | 有効/無効（バッジ表示） |
| 操作 | 有効化/無効化ボタン、削除ボタン |

### 固定者の操作

固定者に対する操作は以下の3種類：

| 操作 | 説明 |
|------|------|
| 優先順位変更 | 数値入力フィールドで直接変更（1〜99、変更時に自動送信） |
| 有効/無効切替 | トグルボタンで有効化・無効化を切り替え |
| 削除 | 論理削除（deleted_at を設定、確認ダイアログあり） |

> 「編集画面」は存在しない。一覧画面上でインライン操作する。

### 固定者登録

1. 店舗を選択（サイドバーで単一店舗選択時は自動設定）
2. 清掃者を選択（店舗選択後にAPI経由で動的取得、既登録者は除外）
3. 優先順位を入力（デフォルト: 1、範囲: 1〜99）
4. 追加ボタンで保存

## 急募通知

### 急募条件

以下のいずれかに該当すると【急募】としてPush配信：

| 条件 | 説明 |
|------|------|
| 固定者全員NG | 全ての固定者が辞退 |
| 延長NO | 延長依頼を担当者が拒否 |
| 未充足 | 清掃予定の2時間前でも未割当 |

### 急募通知メッセージ

```
【急募】清掃スタッフ募集！

📍 場所: {sales_area_name}
📅 日時: {date} {time}
💰 報酬: {reward}円

⚠️ お急ぎの案件です

▼ 詳細・応募はこちら
{application_url}
```

### 急募の送信対象

- 該当店舗に登録済みの全清掃者
- `is_active = true` の清掃者のみ

## 固定者の応答記録

### notification_logs

| カラム | 説明 |
|--------|------|
| cleaner_id | 通知先清掃者 |
| job_id | 案件ID |
| type | `fixed`（固定者通知） |
| sent_at | 送信日時 |
| response | ok / ng / timeout |
| responded_at | 応答日時 |
